Claude Inference Hooks

How a company inspects — and optionally blocks — every prompt its employees send to Claude. One page for engineers. Feature docs: Inference hooks overview.

The idea in one paragraph

With Claude Enterprise, before Claude processes a prompt from your organization (claude.ai, Claude Code, Cowork), Anthropic pauses and sends the whole conversation to an HTTPS server you run — the "AI security server". Your server answers one of two verdicts: {"action":"allow"} or {"action":"deny","deny_reason":"..."}. Allow → the model runs, the user notices nothing. Deny → the user sees your reason instead of an answer. With tool-call validation on, Claude's tool calls get the same treatment before they run. Key inversion to internalize: you don't call Anthropic — Anthropic calls you.

The request body (the "frame") carries the transcript, who sent it (actor), which app (source.application), model, and session — never system prompts or raw file bytes. Full schemas and field names: Develop an Inference hooks integration.

Enforce, inform, or off — the company's dial

This is the part most people miss: enforcement is not in your code. It's set in the admin console — claude.ai → Organization settings → Data and privacy → Inference hooks (requires the Owner or Primary owner role). Step-by-step setup: Configure Inference hooks.

StateConsole settingWhat actually happens
OffEnforce verdicts toggle offYour server is never contacted. Zero effect on anyone.
Inform ("Shadow mode")Enforce verdicts on + Mode = Shadow modeYour server receives every prompt and votes — and the vote is ignored. Nobody is blocked, nobody notices. This is how you tune policy on real traffic. A rollout % lets you start with a slice of requests.
EnforceEnforce verdicts on + Mode = Allow/Block the requestA deny blocks the user and shows your deny_reason. The Allow/Block choice is failure handling: if your server is down or slow, do prompts pass uninspected (fail-open) or is everyone blocked (fail-closed)?

Changes propagate in about a minute. Safe rollout order: Off → Shadow at 10% → Shadow at 100% → Enforce fail-open → (maybe) fail-closed.

The rules that bite

A deny is HTTP 200. {"action":"deny", ...}. Returning 403/500 is not a block — it's a webhook failure, which triggers failure handling instead of your verdict. Sustained failures trip a circuit breaker: Anthropic stops calling you entirely until your server recovers.
You have ~5 seconds, total. The verdict timeout (configurable 1–10,000 ms, default 5,000) covers the entire exchange — TLS handshake included. Anthropic retries once, only on connection failure, with the same webhook-id (use it as an idempotency key).
Bodies are big. Transcripts are sent untruncated, up to 64 MiB. Anything in the path with a small body limit silently breaks you — AWS API Gateway (10 MB cap) is out; ALB/NLB and Kong defaults are fine.
The URL must be genuinely public. https:// on port 443, public IPv4, public-CA certificate, answers without redirects. Tunnels (ngrok etc.) are blocked. Requests come only from 160.79.106.0/24 — allowlist it at the gateway (Anthropic IP ranges), but real authentication is the signature below.

The smallest working server

from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer

class Verdict(BaseHTTPRequestHandler):
    protocol_version = "HTTP/1.1"
    def do_POST(self):
        self.rfile.read(int(self.headers.get("Content-Length", 0)))  # drain body
        v = b'{"action": "allow"}'
        self.send_response(200)
        self.send_header("Content-Type", "application/json")
        self.send_header("Content-Length", str(len(v)))
        self.end_headers()
        self.wfile.write(v)

ThreadingHTTPServer(("", 8000), Verdict).serve_forever()

Before enforcing, add signature verification: every request is signed per the Standard Webhooks spec — HMAC-SHA256 over webhook-id.webhook-timestamp.body with the whsec_… secret the console shows once at setup. Reference implementations in 7 languages: Verify the signature.

Auditing

Every denial is recorded in the org's compliance Activity Feed as inference_hooks_request_denied, carrying the reference_id your server returned — so you can join Anthropic's record to your own logs. Circuit-breaker trips and config changes land there too. The console's Inference hooks page shows endpoint health live: failures per minute, block rate, recent errors.
